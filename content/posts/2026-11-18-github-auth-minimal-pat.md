给编码 agent 配 GitHub 访问时撞了限流：匿名调 API 只有 60 次/小时，两个 agent 一跑就撞墙。它给出的解法很干脆——装个 gh CLI、登录一下就能解除。装之前我留了个心眼，先翻了下 GitHub 的授权页面（Settings → Applications），结果限流还没解决，先看到了一条解释不通的记录：**两处「OpenCode Console」授权，其中一条显示「从未使用」**。我只记得登录 opencode 控制台时选过一次 GitHub 验证，什么时候授权了两次？

## 一、两条授权从哪来

GitHub 有两套互不相干的授权体系：**OAuth Apps** 是用户级登录授权（「Sign in with GitHub」那类），**GitHub Apps** 是应用安装/集成（拉仓库、开 PR 那类）。同一个产品两套都注册，就会在两个页面各留一条——OpenCode Console 正好两套都有。

排查方法简单粗暴：**两条都撤销，重新登录一次，看哪条回来**。

结果很说明问题：

- GitHub App 那条（显示 4 个月内用过）没回来——它是旧版控制台的登录通道，控制台改版后已经弃用，纯属历史遗留；
- OAuth 那条登录即重建——它才是现行登录通道。

至于「从未使用」的谜底也顺手揭开了：GitHub 的 Last used 只统计应用**拿令牌去调 GitHub API** 的行为，登录时交换一次身份不计入。所以这条授权从创建那天起就显示从未使用——不是授权没生效，而是它除了登录没干过别的。控制台升级换过一次登录实现，旧通道留下的授权就成了僵尸条目。

## 二、拆开看权限：都是登录级

两条都点进去逐条看过权限清单：

| 授权 | 权限清单 | 仓库/代码/组织权限 |
|---|---|---|
| GitHub App 版（旧） | 验证身份、知道你能访问哪些资源、代表你操作、查看邮箱 | 无，且注明「未安装到任何账户」 |
| OAuth App 版（新） | 读用户资料、只读邮箱 | 无 |

「用 GitHub 登录」能给的就是这组最小权限——它根本没有动仓库的能力。弄清来龙去脉后，把闲置的旧条目撤掉，顺带清了另一条从未使用的授权，PAT 两栏保持 0，这页就算干净了。

## 三、gh CLI：为限流交全家桶，不值

agent 的建议本意没错——GitHub API 匿名调用 60 次/小时，带上任何有效令牌就是 5000 次/小时。但注意一个关键点：**升额度看的是「有没有令牌」，跟令牌权限多大完全无关**。

而 gh 的浏览器授权申请的是干活全家桶：repo 读写、workflow、组织信息……因为它是全能 CLI，不是因为限流需要这些。拿全家桶去换限流额度，这笔账不划算。更妙的是这几个 agent 的行为是「先看有没有 gh，没有才退回 curl」——不装 gh，它们反而落到更可控的 curl 路线上。

## 四、最小权限令牌实操

方案定为一把**细粒度 PAT**（fine-grained personal access token）：

- Repository access 选 **Public repositories (read-only)**——公开仓库本来人人可读，零增量权限；
- 有效期 90 天，到期自动作废，忘了清理也不留活口；
- 账户权限保持 0（最多补「只读资料/邮箱」两勾，不影响限流）。

喂给工具的姿势有个小坑：`gh auth login --with-token` 是**从标准输入读令牌、不给任何提示**的——回车后「没反应」是正常的，它在等你喂输入：

```bash
# 交互式：粘贴令牌后回车，再按 Ctrl+D 结束输入
gh auth login --with-token

# 或从文件喂，令牌不进 shell 历史
gh auth login --with-token < token.txt
```

其实可以不 login——gh 和 curl 都认环境变量：

```bash
export GH_TOKEN=<你的令牌>
gh auth status        # 确认显示 Token: github_pat_***，而不是 OAuth
gh api /rate_limit    # resources.core.limit 应为 5000
```

验证通过的标准：`gh auth status` 显示 **Token** 登录，且 GitHub 的授权列表里永远不会出现「GitHub CLI」条目——浏览器 OAuth 那条路从头到尾没走过。curl 直接调 API 时带上 `Authorization: Bearer` 头，同样享受 5000 次/小时。

## 五、结论与取舍

- **只为解除限流、读公开数据**（自用和 agent 场景）：细粒度 PAT + 公开只读 + 90 天过期就是全部答案，权限几乎为零。
- **真拿 gh 干活**（提 PR、发 release、管 Actions）：浏览器授权的全家桶是干活需求，该给就给——但要明白那是功能的代价，不是限流的代价，两码事。
- 顺带的教训：授权页里每条都点进去看一眼权限清单。重新授权永远只要一次点击，而留着的闲置授权是永久暴露面——**能撤就撤，撤错了大不了再授权一遍**。

一句话收尾：权限大小的唯一开关是「你签发什么令牌」，跟走 gh 还是 curl、装没装工具，都没有关系。
